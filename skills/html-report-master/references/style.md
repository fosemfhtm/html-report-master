# 문체 사례

실제로 지적받은 문장과 고친 문장을 유형별로 모았다. 프로젝트 이름과 수치는 가상의 예로 바꿨고, 지적의 내용과 고친 방향은 그대로다. 예에 나오는 'PlanLab'은 신호 계획 후보를 만들어 시뮬레이션으로 평가하는 가상의 도구다. 새 문장은 같은 유형의 사례와 대조해 고친다.

## 1. 자리별 문장 형태

| 자리 | 형태 | 예 |
|---|---|---|
| 제목, 장 이름, 카드 제목 | 명사형 | 시뮬레이터와 화면의 통합 |
| 카드 요점, 표 칸, 라벨 | 짧은 명사형 | 결과를 시간 구간 단위로 읽어 재생 |
| lead, 자막, 본문 | "~한다" 평서문 | PlanLab은 후보를 대상 네트워크에서 하나씩 시뮬레이션해 평균 통행시간을 측정한다. |

| 고칠 제목 | 고친 제목 |
|---|---|
| 한 번 만들어 봤다 | 시뮬레이션 기반 신호 최적화 웹앱 |
| 해법 예시가 아닌 … 계약서다 | (부정형과 비유를 지우고 장의 주제를 명사형으로) |
| 누가 기록을 줄였나 | 통행시간 감소의 출처 |

## 2. 설명 중심 서술

설명은 "무엇을 한다"와 "왜, 그래서 무엇이 되는지"를 함께 담는다. 사실만 이어 쓴 자막은 줄인 뒤에도 "나열하는 느낌"이라는 평을 받았다.

| 나열 | 설명 |
|---|---|
| 구조 함수는 현시가 쓰는 차로와 이동류를 돌려주고, 이동류의 회전 방향도 함수로 묻는다. | 정책은 "이 현시의 진입 차로"처럼 현시와의 관계로 차로를 가리킨다. 그래서 현시 수나 차로 수가 다른 교차로에도 수정 없이 적용할 수 있다. |
| 입력은 과제, 규칙, 경로, 함수 목록, 출력 형식을 담는다. | PlanLab은 생성기에 정책 규칙과 쓸 수 있는 함수 목록을 주고 후보를 받는다. 규칙에 맞지 않는 후보는 오류 내용을 붙여 한 번 다시 받는다. |
| 최종 정책은 근접·대기 수요와 … 보너스 10 때문에 P1을 유지한다. | 최종 정책은 정지선 근처 차량 수와 가장 긴 대기열을 더하고, 현재 현시에는 차량 10대만큼 더한다. 그래서 다른 현시가 10대 넘게 앞설 때만 현시를 바꾼다. |
| 차량 수와 입구 대기열은 현재 상태다. 직전 흐름은 … | 모형은 현재 차량 수와 직전 흐름을 함께 읽는다. 차량 수만으로는 정체가 막 생긴 경우와 오래 이어진 경우를 구분할 수 없기 때문이다. |

## 3. 행위자 주어와 능동형

대상이나 과정을 주어로 세우면 누가 무엇을 하는지 흐려진다. 같이 작업한 사람도 이런 문장을 이해하지 못했다.

| 고칠 문장 | 원인 | 고친 문장 |
|---|---|---|
| 각 후보는 … 평가된다 | 대상 주어, 수동형 | PlanLab은 후보를 … 시뮬레이션해 평균 통행시간을 측정한다. |
| 국소 수정은 평균 통행시간을 줄였다 | 과정 주어 | PlanLab은 조건문의 한 분기를 바꿔 평균 통행시간을 210 s에서 202 s로 줄였다. |
| 이 예의 점수는 … 더한 값이다 | 어색한 주어 | 예시 정책은 현시마다 진입 차로의 대기 차량 수를 더해 점수로 쓴다. |
| 처음 낮춘 것은 생성기의 후보였고 | 영어 강조 구문 | 첫 라운드에서는 생성기의 후보가 가장 좋은 결과를 만들었고, 그 뒤의 개선은 모두 국소 수정에서 나왔다. |

## 4. 국내 발표 말투

| 고칠 표현 | 원문 | 바꿀 표현 |
|---|---|---|
| 양보한다 | trade off | 한계가 있다 |
| 돈다 | runs | 실행한다 |
| 관계로 차로를 지정한다 | refers through relations | 현시와의 관계로 차로를 가리킨다 |
| 함께 진행하는 이동류의 묶음 | a set of movements that proceed together | 동시에 녹색 신호를 받는 이동류의 조합 (교통 연구자 대상이면 정의 생략) |
| 최고 평균 통행시간 | best average travel time | 가장 좋은 후보의 평균 통행시간 |
| 직접 찾은 정책 | policy found directly | 직접 탐색한 정책 |
| 미리 만들어 둔다 | 구어체 | 합성한다 |
| 상위 8개가 다음 단계로 간다 | 구어체 | 그 가운데 상위 8개를 수정 대상으로 고른다 |
| 좋고 짧은 것을 골라 둔다 | 구어체 | 성능이 좋고 짧은 후보를 선별한다 |

## 5. 간결성: 삭제한 문구

청중의 판단에 쓰이지 않는 문구는 지운다.

**하지 않는 일과 제외한 것**

| 지운 문구 | 처리 |
|---|---|
| 시드, 수요 번호, 파일 경로는 넣지 않는다 | 삭제 |
| "쓸 수 없는 질문" 패널 | 삭제 |
| 줄 그은 "온라인 호출" | 삭제 |
| 교차로 형태가 다른 네트워크에는 적용되지 않음 | 빈칸 "–" |
| 차로 번호를 쓰지 않고 관계로 | "관계로" |

**자료 자체에 대한 설명**

| 지운 문구 | 처리 |
|---|---|
| 설명용 예시 교차로…, 실제 3라운드 입력… | 삭제 |
| 계보는 실험 B의 실제 채택 수정, 실제 아카이브… | 삭제 |
| 막대를 누르면…, 차로를 눌러 보세요 | 문구만 삭제, 클릭 기능은 유지 |
| 실제 데이터와 예시 데이터의 구분 | 작은 `실제` / `예시` 태그로 유지 |

**되풀이**
- 제목과 자막이 같은 말을 표현만 바꿔 되풀이했다.
- 화면에 떠 있는 숫자를 문장에서 다시 늘어놓았다.
- 고친 방법: 제목은 주제, 문장은 의미, 그림은 숫자로 역할을 나눈다.

## 6. 용어

| 유형 | 예 | 처리 |
|---|---|---|
| 작업 중에 생긴 내부 용어 | 엘리트, 이웃, 프리미티브, 코퍼스, 아카이브, 웜업, 실험 B, A/B/C, R0–R3, 버전 이름(V1, v2_final) | 뜻을 풀어 쓴 표현으로 바꾼다 |
| 청중이 처음 듣는 말 | 그 분야에서도 드문 지표 이름 | 쓰지 않거나 처음 나올 때 푼다 |
| 코드, 함수 이름, 프롬프트 원문 | `lib.phase_incoming_near_vehicle_count_sum` | 뜻으로 부른다: "근처 차량 + 지금 현시 가산점" |
| 국내 교통공학 용어 | 현시, 이동류, 녹색시간, 주기, 오프셋, 지체, 대기행렬, LOS, TOD | 정의 없이 쓴다 |

## 7. 분량과 숫자

- 자막과 lead는 한두 문장으로 쓴다. 평균 55자, 최대 98자의 자막은 청중이 읽는 사이 화면이 넘어갔다.
- lead와 자막에서는 한 단위에 숫자 하나. 그림이 숫자를 보여 주고, 문장은 그 숫자의 의미를 말한다. 방법 본문에서 식에 숫자를 넣어 계산해 보이는 것은 이 규칙과 별개다.
- 세부 수치(웜업 600 s, 제어 3,600 s, 선택 비중 85%·15%)는 발표 대본과 부록으로 옮긴다.

## 8. 사실의 범위

- **인과.** 데이터로 확인한 인과만 쓴다. "함수가 쌓여서 통행시간이 줄었다"는 확인하지 못한 인과라서, 두 변화를 나란히 적었다.
- **사용자의 설명.** 원인과 수치를 살려 옮긴다. "따로 떨어진 앱"이라는 요약은 이전 앱의 실제 한계를 가렸다. 실제 한계는 시뮬레이터 외부 연동 구조와, 매 스텝 값을 모은 재생 파일이 결과 1건당 수 GB에 이른다는 점이었다.
- **개념 구분.** TOD와 RL은 따로 쓴다.
  - TOD: 시간대별 고정 계획, 탐색으로 찾는다.
  - RL: 결정 간격마다 신호를 바꾸는 정책, 학습으로 얻는다.
