# 모션 발표

말로 발표하는 자료는 모션 발표로 만든다. 1920×1080 무대 위에서 장면을 스텝 단위로 재생하고, 스텝이 끝나면 멈춘다. 발표자는 Space로 다음 생각을 꺼낸다. 틀은 `assets/motion_template.html`, 부품은 `assets/motion_gallery.html`(MS 그룹)에 있다.

읽고 공유하는 자료는 보고서로 만든다. 이야기 잡기, 계속 쓰는 작은 예, 숫자 대입, 사실 확인은 두 형태가 같다.

## 1. 진행

1. **스토리보드를 승인받는다.** HTML 전에 장면마다 아래 표를 보여 준다. 자막까지 실제 문장으로 쓴다.

   | 장면 | 섹션 | 제목(주장 문장) | 무대 상태 | 스텝별 자막 | 모션 |
   |---|---|---|---|---|---|
   | formula | 대기 시간 | 평균 대기 시간은 줄 선 사람 수를 도착률로 나눈 값이다 | 카페 줄, 손님 22명 | ① 손님이 줄에 서서 22명이 된다 ② 22 ÷ 2 = 11분이다 | ① 손님 차례로 등장 ② 식 카드에 숫자 채우기, 세기 |

2. **틀 위에서 만든다.** `motion_template.html`을 복사하고 아래 "장면" 스크립트만 바꾼다. 엔진은 고치지 않는다.
3. **스텝마다 화면을 본다.** `scripts/screenshot.mjs --motion`이 스텝이 끝난 화면을 모두 찍고 검사한다.
4. **본편과 부록을 나눈다.** 질의응답용 세부는 부록 장면으로 뒤에 둔다. 부록은 본편 장면을 다시 만들지 않고 세부 스텝만 더한다.

## 2. 화면

- **머리.** 섹션 이름(eyebrow)과 주장 문장 제목. 필요하면 보조 줄 하나.
- **무대와 작업대.** 계속 쓰는 예는 장면이 바뀌어도 왼쪽 같은 자리(`k.L.stage`)에 둔다. 설명은 오른쪽 작업대(`k.L.bench`)에서 바뀐다. 독자는 예를 다시 해석하지 않고 바뀐 곳만 본다. 무대가 필요 없는 장면은 `k.L.full`을 쓴다.
- **실물로 그린다.** 지도는 길과 지점으로, 후보는 점으로, 프로그램은 코드 줄로, 결과는 값이 적힌 막대로 그린다. 이름표 상자만 놓지 않는다.
- **식 카드.** 위 줄은 말 풀이, 아래는 실제 코드. 코드도 읽히는 크기(20px 이상)와 대비로 둔다.
- **결정은 분해한 수치로.** 점수를 성분 누적 막대로 나누고, 아래 한 줄에 판정을 쓴다. 예: "3번이 2번보다 4.2 낮아 3번으로 간다".
- **역할 색.** 한 덱 안에서 한 역할은 늘 같은 색이다. 예: 제안은 남색, 평가는 주황, 편집은 노랑, 라이브러리·우리 방법은 대표색, 채택은 초록, 실패는 빨강. 진행 캡슐(`nav`)도 같은 색 규칙을 따른다.
- **결과에는 기준선.** 막대 위에 비교 기준을 점선과 이름으로 겹친다.
- **글자.** 제목 48, 소제목 34·28, 본문 24·22, 보조 19, 자막 30px. 17px 아래는 쓰지 않는다. 회색 글자도 배경과 대비가 분명해야 한다.

## 3. 말투

- **제목은 주장 문장이다.** "최종 정책은 다른 현시가 10대 넘게 앞설 때만 현시를 바꾼다"처럼 그 장면이 보여 주는 결론을 쓴다. 보고서의 명사구 제목 규칙과 다르다.
- **자막은 스텝마다 한두 문장이다.** 일을 하는 주체를 주어로, 현재형 평서문으로 쓴다. 첫 문장은 지금 화면에서 일어난 일, 둘째 문장은 그 결과나 뜻("그래서 …")이다.
- **보여 준 뒤 이름 붙인다.** "…바뀐 트리를 남기고, 이 과정을 국소 편집이라고 부른다."
- **숫자는 화면에 있는 값.** 자막의 숫자는 지금 보이는 예에서 가져온다(P4 점수 10, 199.7 s → 190.1 s).
- **제목을 자막에서 되풀이하지 않는다.** 제목은 결론, 자막은 지금 볼 곳과 그 뜻이다.
- 보고서의 글 규칙(부정어 대비, 메타 서술, 방어 문구 금지)을 그대로 따른다.

## 4. 모션 어휘

움직임은 과정을 설명할 때만 쓴다. 장식 움직임은 넣지 않는다.

| 움직임 | 설명하는 것 | 엔진 |
|---|---|---|
| 칸 세며 덜어 내기 | 걸러 내기, 선별 | 단위 격자(1칸 = n개) + `k.to`로 칸을 이유별 더미로 옮기기 + `k.count` |
| 스포트라이트 | 지금 볼 곳 하나 | `k.focus(대상, 나머지)` — 대상은 옅은 대표색 면, 나머지는 30%로 어둡게 |
| 밑줄 | 문장 안의 핵심 구절 | `k.underline` |
| 따라가기 | 한 건이 여러 단계를 지난다 | 표식 하나를 `k.to`로 옮기며 단계마다 `k.focus` |
| 전후 변형 | 같은 대상이 개선 뒤 어떻게 바뀌었나 | 같은 막대를 `k.to`로 줄이며 `k.count` |
| 접기 | 여러 개가 하나로 묶인다 | `k.fold` |
| 통과·실패 | 기준을 넘었나 | `k.mark('ok' / 'bad')` — 짚는 데는 쓰지 않는다 |
| 선 그리기 | 진행한 만큼의 기록, 경로 | `k.draw` |
| 타자 | 무언가가 출력을 만든다 | `k.type` |
| 차례로 나타나기 | 같은 종류 여러 개 | `k.appear(…, {stagger})` |
| 배경 흐름 | 시스템이 계속 돈다(손님, 차량, 요청) | `k.ambient` |

- **템포.** 하나의 움직임은 0.2~0.6초, `power2` 곡선. 스텝 하나는 2~5초. 길어지면 스텝을 나눈다.
- **스텝 하나에 생각 하나.** 자막 하나가 설명할 수 있는 만큼만 움직인다.

## 5. 자주 놓치는 것

- **제목과 자막이 같은 말.** 자막은 제목이 말하지 않은 "지금 볼 곳"을 짚는다.
- **읽히지 않는 코드와 트리.** 30% 투명도 회색, 17px 코드, 작은 트리 세 개를 나란히 둔 화면은 투영하면 색 덩어리가 된다. 강조할 부분만 크게 보이거나 하나씩 확대한다.
- **같은 내용의 장면 중복.** 본편과 부록에 같은 장면을 제목만 바꿔 두지 않는다.
- **손으로 쓴 좌표.** 장면마다 절대 좌표를 새로 정하면 정렬이 흐트러진다. `k.L`과 `k.grid`로 나눈다.
- **자막 띠 침범.** 본문은 y 914 위에서 끝낸다. 자막(y 944부터)을 가리지 않는다.
- **테마에서 사라지는 색.** 색은 모두 CSS 변수(`var(--…)`)로 쓴다. 고정 색은 T 키로 테마를 바꾸면 배경에 묻힌다.
- **노란 상자로 짚기.** 짚을 때 테두리 상자를 두르면 화면이 어수선해진다. 스포트라이트와 밑줄로 짚는다.
- **작은 점 수백 개.** 무작위 점 구름은 투영하면 뜻이 사라진다. 셀 수 있는 크기의 칸·기호로 그리고 칸 하나가 몇 개인지 적는다.

## 6. 엔진

```js
deck.config({ langs: ['ko', 'en'] });             // 한 언어면 ['ko'], 글은 문자열로
deck.scene('formula', { eyebrow: '대기 시간', title: '평균 대기 시간은 …', nav: { items: ['문제', '원인', '결과'], on: 1 } }, (s, k) => {
  const f = k.formula(s, k.L.bench.x, k.L.bench.y, k.L.bench.w, '평균 대기 시간 = 줄 선 사람 ÷ 도착률', 'W = L / λ');
  k.hide(f);                                        // 스텝에서 나타날 요소는 숨겨 둔다
  k.step('자막 한두 문장', () => { k.appear(f); }); // 시각은 스텝 시작부터 초
});
deck.start();
```

- 글은 `'한국어'` 또는 `['한국어', 'English']`. SVG 글자는 `k.sv('text', {...}, 부모, ['한국어', 'English'])`.
- 키: Space·→ 다음, ← 이전, G 장면 목록, K 연속 재생, T 테마, L 언어(두 언어일 때), F 전체 화면. 주소 끝 `#장면id`로 그 장면부터 연다.
- 검사 창구: `window.__deck.beats`, `seekBeat(i)`, `seekTime(t)`, `sceneStart(id)`, `setTheme`, `setLang`.

## 8. 장면 부품 (MS)

`assets/motion_gallery.html`에 있는 장면이다. 브라우저로 열어 Space로 스텝을 넘기며 보고, 고른 장면의 `deck.scene(...)` 블록을 발표 파일로 옮긴 뒤 내용을 바꾼다. 예시 주제는 점심시간 카페 대기열이다(`cafeStage`).

| ID | 이름 | 언제 쓰나 | 핵심 요소 |
|---|---|---|---|
| MS-01 | 표지 | 첫 화면에서 주제와 결론 숫자를 함께 보인다 | 큰 제목, 한 줄 부제, 움직이는 기준 예제 미리보기 |
| MS-02 | 큰 숫자와 원인 분해 | 문제의 크기를 숫자 하나로 보이고 원인으로 나눈다 | 세며 커지는 숫자, 원인별로 갈라지는 막대 |
| MS-03 | 기존 방법 비교 카드 | 기존 방법들을 같은 기준으로 하나씩 짚는다 | 2×2 카드, 스포트라이트, 밑줄 |
| MS-04 | 같은 자리 예제와 식 카드 | 식의 각 항이 예의 어디에서 나오는지 잇는다 | 왼쪽 기준 예제, 식 카드, 숫자 채우기와 세기 |
| MS-05 | 단위 격자 깔때기 | 많은 대상을 단계별로 걸러 남은 수를 보인다 | 1칸 = 10편 격자, 이유별 더미로 옮기기, 남은 수 세기 |
| MS-06 | 과정 따라가기 | 한 건이 여러 단계를 지나는 동안 각 단계의 몫을 보인다 | 실물 단계 그림, 이동하는 표식, 단계별 스포트라이트와 시간 |
| MS-07 | 전과 후 변형 | 같은 항목이 개선 뒤 얼마나 줄었는지 보인다 | 같은 막대의 변형, 합계 괄호와 차이 |
| MS-08 | 분해 막대와 판정 줄 | 비용과 효과를 나란히 두고 선택 이유를 보인다 | 짝 막대와 범례, 예산 선, 판정 한 줄, 선택 행 스포트라이트 |
| MS-09 | 결과 막대와 기준선 | 결과를 두 조건에서 목표선과 함께 비교한다 | 두 패널, 개선안 대표색, 점선 목표선과 이름 |
| MS-10 | 결론 세 줄 | 결론을 숫자 하나와 문장 하나씩 정리한다 | 차례로 나타나는 세 줄 |
